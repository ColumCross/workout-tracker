# Workout Tracker

A personal workout tracker for recording machines, sets, repetitions, and weights, then reviewing saved workouts from a phone or laptop. Each user's workout data is private.

## Status

Early setup; initial commit. This is pre-Alpha and pre-deslopification. The app is still in a non-functional state.

## Goals and scope

- Keep infrastructure and operating costs at $0 within free-tier limits.
- Use one repository and minimize backend development and infrastructure management.
- Build for the web first with future native mobile compatibility.
- Keep the design simple, maintainable, and extensible.
- Start with workout logging and basic history. CSV export and richer reporting can follow.

Third-party fitness integrations, external data synchronization, and full offline operation are out of scope. A locally persisted draft may preserve work across accidental tab closure; it is not synchronized across devices.

## Architecture

The Expo client handles screens, the rest timer, draft persistence, and immediate validation. Supabase provides Auth, the PostgreSQL database, the Data API, Edge Functions, and database-side operations. A separate application server is not currently required.

Every application record has an explicit authenticated owner. A complete workout is submitted through a PostgreSQL RPC in one transaction; direct client table writes remain blocked. The ID is generated by an authenticated Supabase Edge Function with the server clock and no database write.

### Workout aggregation API

`GET /functions/v1/getWorkoutID` requires an authenticated user and returns a noncached ID in this format:

```text
<server Unix milliseconds>-<16 random digits>-<Supabase user UUID>
```

It does not create a database record. `POST /rest/v1/rpc/saveWorkout` accepts one JSONB argument named `payload`. A new ID inserts the workout, exercises, and sets atomically. An already saved ID returns success without examining or changing its submitted contents. There is no editing API.

## Data model

| Entity | Meaning |
| --- | --- |
| User | Supabase Auth identity with application profile data in `public.users` |
| Workout | A session containing machine entries |
| Workout machine entry | A named machine used within this particular workout, containing sets |
| Set | Rep count and one weight applying to the entire set |

A user-owned machine catalog may be referenced by workout entries; its attributes and maintenance API are still to be finalized. Individual repetitions do not need separate records.

## Core workflow

1. Sign in and choose to start a workout or review history.
2. Select a machine and record sets while a client-side rest timer runs.
3. End the machine, then add another machine or finish the workout.
4. Submit the workout; preserve the draft if submission fails.
5. Clear the draft after confirmed success and make the saved workout available across devices.

Workouts belong to the date they started. `start_time` is derived from the server-generated timestamp embedded in the workout ID; `end_time` is the database insertion time. Set weights are nonnegative integer grams in `weight_g`.

## Repository and development

Keep the existing Expo layout. Store backend configuration in `supabase/config.toml`, versioned SQL changes in `supabase/migrations/`, and Edge Functions in `supabase/functions/`.

Use the repository's Nix development shell and the Supabase CLI provided by it. From the repository root:

```bash
nix develop
supabase login
supabase link --project-ref YOUR_PROJECT_REF
```

Run only missing setup steps. Create migrations with `supabase migration new NAME`; review them before applying to the linked project. SQL and Edge Functions deploy separately:

```bash
supabase db push --linked --dry-run
supabase db push --linked
supabase functions deploy getWorkoutID
```

Local Supabase development via `supabase start` requires a supported container runtime. `db push` does not deploy Edge Functions, Auth provider settings, or the Expo web application.

GitHub source control and database deployment are separate unless automation is configured. Keep hosted preview branching disabled for the $0 budget. Free services have quotas and availability limitations; exceeding them must not trigger a paid upgrade.

## Security and configuration

Scope all private reads and writes to the authenticated user, including child records. Child foreign keys include the user identifier so mismatched parent ownership cannot be stored. Prevent direct API access that bypasses required business rules. Validate on the backend even when the client already validates.

Keep secrets in ignored environment files or provider settings. Commit placeholder examples and migrations, not credentials or user data. Hosted Google OAuth settings and frontend deployment require configuration beyond database migrations.

# Workout Tracker Client

Expo Router client for the workout-tracker UI prototype. It runs entirely in memory and does not require Supabase credentials, authentication, network access, or local persistence.

## Run

```bash
npm install
npx expo start
```

Use `npx expo start --web` for the web preview.

## Prototype flow

The preview implements the placeholder entry screen, New workout flow, free-text exercise naming and renaming, a 00:00 to 10:00 drag-only rotary rest-duration picker, set validation, pause/resume, and an in-memory summary. The circular timer is used for selection and focused rest: the blue pin is shown only while selecting, while an unpinned white ring counts down during rest. Set entry instead keeps the same countdown in a fixed top time-and-pause strip. Reports is intentionally disabled. Summary Next and End both reset to the placeholder entry screen.

The timer selector uses `react-native-rotary-timer`; React Native Paper and `@expo/vector-icons` supply the standard controls, dialogs, and icons. Roboto is bundled with the client, and the app follows the device color scheme automatically.

`patches/react-native-svg+15.16.0.patch` fixes a React Native SVG web-style update incompatibility exposed by the rotary selector. `patches/react-native-rotary-timer+0.4.4.patch` removes tap-to-set so dragging the pin is the only duration adjustment. Both are automatically reapplied after `npm install`.
